8 个 Skill 串联「需求录入 → PRD → 原型 → 设计 → 手册 → 视频 → 发布通知」完整链路；PRD 发布前可选先经 LD-PRD-Reviewer 审查（红色分支路径）。

3LD 家族通用机制（新人必读）

所有 Skill 共享的六条铁律，理解了它们就理解了 LD 家族一半的设计。

🔐 统一凭证中心

所有凭证集中存放在 ~/.workbuddy/config/_ld_shared/credentials.json（权限 0600），由 ld_credentials.py 统一读写。探测链：环境变量 → 凭证中心 → 旧 config → rc 文件。首次配置一次，全部 Skill 永久复用，之后不会被重复询问。

🚧 硬门禁（Hard Gate）

每个 Skill 的第一步都是环境检查（check）：TAPD 令牌、飞书授权、机器人凭证等。check 不通过 → 立即终止，禁止任何后续写操作；授权过期时脚本会自动发起授权流程，只需点击/扫码确认。飞书授权过期会给出 AUTH_URL + 二维码图片。

👀 单次确认门禁

AI 的产出（Story 字段、手册内容、FEATURE 卡片等）必须先展示预览，用户确认后才落库。预览即所见即所得——例如建 Story 时展示的 description.html 与最终落库内容完全一致。

🗂 关联产物表（单一事实来源）

TAPD 需求描述采用六段式模板，第「六、补充信息」节承载统一关联产物表：PRD / 原型 / 设计 / 手册 / 视频各占一行、互不覆盖。跨 Skill 规范收敛到单一文件 ~/.workbuddy/skills/_ld_shared/references/ld-artifact-table-conventions.md（5 条强制约束 + 范本实现 + 历史踩坑），任何涉及写表的改动都先读它。Release-Notifier 提取关联产物时只读 Story 自定义字段（six/seven/eight），不从描述二次解析。

📐 章节按「入口 × 对象」划界（手册）

手册章节归属不按 Story 划、按功能入口 × 目标对象划：同一功能迭代并入已有章节（merge，小节级合并、四节按语义对齐、FAQ 去重、原有截图沿用），只有全新功能域才新增章节（new）。写文档前必须跑 route 判归属，三档结果 merge / confirm / new 对应退出码 0 / 10 / 11；合并必须用 --drop-section 删源章，否则同一功能会留两份。

🧪 停靠点与自检：不许静默放行

视频三个停靠点（素材匹配 / 分镜文案 / 样片）是硬门禁：未 approve 则下游命令直接拒绝；确认后若内容再改，指纹失配自动变「已失效」需重签；确需跳过必须 --allow-unreviewed 并留痕到 pending.md。手册 audit 六类体检（篇幅预算 / 同质图 / 重复事实 / 实现细节 / FAQ 冗余 / 小节零图）、视频 verify 14 项，任一不过即退出码 1。

5新人快速上手

按顺序完成 4 步，即可跑通整条 PM 工作流。

  1. 配置凭证（仅一次）
    对助手说「配置 TAPD 令牌」，按提示提供 TAPD 个人访问令牌；飞书授权在首次发布时扫码完成。所有凭证写入统一凭证中心，之后 8 个 Skill 全部免配置。
  2. 录入需求 → 写 PRD → 审查 → 发布
    「根据这份 Word 录入需求」（父需求必须给，且是未完成 Feature）→ 编写 PRD Markdown → 「审查 PRD」拿六层思考完成度报告并补强 → 「发布 PRD」发到飞书并自动关联 TAPD，mermaid 自动转画板。后续改稿用「更新 PRD」原地覆盖即可，文档链接不变。
  3. 原型部署与设计关联
    前端出原型后「部署原型目录」，得到永久 pages.dev 域名自动写回 TAPD；设计师出稿后「关联 Figma + 需求链接」，设计字段与关联行同步更新。
  4. 上线后：手册 → 视频 → 通知
    「发布手册」（先 route 判归属，merge 进已有章节，写完自动 audit 体检）→「生成产品视频」（手册为文案真源，三个停靠点逐个确认，出完成片可选贴回手册顶部）→「发送发布通知」（FEATURE 卡片推企微群 + 自动发邮件）。
